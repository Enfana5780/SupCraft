# SupCraft：转换模式、输出选项与字体目录

[使用说明](USAGE.md) · [项目首页](../README.md)

## 两种转换模式

| 项目 | 兼容模式 | 现代模式 |
| --- | --- | --- |
| 流程 | ASS → AviSynth / VSFilterMod RGBA 帧 → avs2bdnxml → SUP 或 BDN | ASS → libass / ass2bdnxml → BDN / PNG → SUPer → SUP |
| 环境 | 安装 32 位 AviSynth+；附带 x86 VSFilterMod 和转换器 | 渲染不依赖 AviSynth；SUPer 附带包需要 64 位 Windows |
| 渲染风格 | 更适合按 VSFilter / VSFilterMod 效果制作的历史字幕 | 更适合按 libass / mpv 效果制作的字幕；支持上游 libass 的字体查找和混合处理 |
| 优点 | 可保留该滤镜支持的特有行为；一个核心直接输出 SUP；有裁剪、位图分割和严格写出选项 | 渲染与 PGS 编码分离；libimagequant 量化；SUPer 有解码时序、窗口和调色板更新优化；提供 BT.2020 和亮度缩减 |
| 成本 | 32 位依赖与渲染器配置；逐帧渲染长时间字幕；复杂特效受旧封装器限制 | 两阶段转换，先写 PNG，磁盘和内存占用随特效增长；SUPer 多进程分析有启动成本；不保证每份字幕都比兼容模式快 |
| 字体目录 | 用 FontLoader 同类 GDI API 临时加载，让外部渲染进程可见；完成、失败或取消后卸载 | 使用 `--fontdir` 直接读取字体；递归找到的字体复制到独立任务目录，兼容中文路径与同名文件 |
| HDR | 本 GUI 没有相应转换功能 | 渲染阶段缩减 RGB 亮度；SUP 编码采用 BT.2020 矩阵；这不是完整的 PQ / HLG 色彩管理 |
| 分辨率 | 本 GUI：720p、1080p、1440p、2160p、自定义 Beta（64–4096 像素，Windows） | 本 GUI：720p、1080p；1440p/2160p 仅 BDN，由 1080p PNG 和坐标缩放生成 |
| 尾部保护 | 渲染长度为最后结束时间加两秒；SUP 检查最终 PTS | 核对 BDN 尾部，必要时仅移除临时副本最后事件的 `\fad` 并重试；失败保留临时文件 |

**如何选择：**字幕原本按 VSFilterMod 校对、并使用其专属行为时，先选兼容模式；希望免 AviSynth、读取目录字体或生成 HDR 用 SUP 时，先选现代模式。需比较同一份字幕的关键特效、换行、字距、描边和尾部，才能判断哪个更符合原设计。两种渲染器不能保证像素一致；某些 VSFilterMod 扩展标签不会自动获得 libass 等效实现。

Windows 兼容模式的自定义宽高会直接传入 `MaskSubMod`，由 avs2bdnxml 根据实际帧尺寸写入 SUP；不对 1080p 位图做后期拉伸。随包核心的 SSE2 循环要求宽×高为 4 的倍数；当前界面采用更严格、直观的逐维校验，宽和高各自为 4 的倍数，编辑时显示红色提示并在修正前禁用开始按钮。自定义 BDN 使用 `VideoFormat="宽x高"` 标记，例如 `1440x3200`，不是标准蓝光预设；下游工具可能拒绝该扩展。输出时额外核对 SUP 的显示/清屏画布及窗口尺寸，BDN 的画布、PNG 尺寸和图形边界。标准预设、libass 路线及 Mac 版本保持原有转换行为。

两种模式都能将普通对白、定位、描边、阴影和各自渲染器支持的 ASS 特效变成图形字幕。转换完成后，字体、文字与排版已烘焙进位图，播放端通常无需字体；也失去 ASS 的文字搜索、样式编辑及随播放器重新排版的能力。

SUP 是 PGS 图形流，受到调色板、对象、缓冲容量、带宽与解码时间限制。即使 ASS 渲染器画出了每一帧，也不代表所有高频动画都能无损保留到 SUP；SUPer 为合规可能合并或丢弃事件。BDN 中间资产可以保留更多渲染结果，但下游制作工具同样有自己的限制。本程序的结构验证无法证明所有字幕内容、颜色和动画都正确，仍需播放抽查。

Windows 默认选用 libass。选用 libass 时仅显示 HDR、亮度与 GPU 设置；选用 AviSynth 时仅显示下述四个输出选项，界面不显示组选项标题。默认输出到每个 ASS 自己所在的目录；也可指定统一输出目录。

## 四个输出选项

| 选项 | 实际含义 | 作用与取舍 |
| --- | --- | --- |
| 自动裁剪 `-a1` | 裁去字幕 PNG / 图形对象四周的透明区域，XML 或 SUP 的坐标仍把字幕放在原位置 | 通常节约磁盘、缓冲和编码工作量；不是裁切视频或删掉可见字幕。开启缓冲优化时，核心优先使用分割裁剪策略，关闭此项不保证整帧输出 |
| 调色板 PNG `-p1` | 把 BDN PNG 写成 8 位索引色，而非 32 位 RGBA | 通常更小，适合要求索引 PNG 的制作软件；颜色和透明度量化可能影响渐变、柔光。兼容 SUP 自身仍使用调色板，关闭它不会得到 32 位真彩 SUP |
| PG 缓冲优化 `-b1` | 分析透明空白并分割图形，降低 Presentation Graphics 对象占用的解码缓冲 | 对上下分离、稀疏分布的字幕有帮助；可能增加对象和处理量，不保证总文件更小。不是 GPU 开关，也不是给电脑分配更多内存 |
| 严格 SUP 写出 `-z1` | 对兼容核心中的缓冲容量和调色板数量作更严格的 epoch 切换检查，源码涉及 4 MiB 缓冲、8 个调色板 | 可能提高部分设备兼容性，也可能增加刷新和文件体积、降低缓冲复用；不保证完整蓝光合规，不修复字体或渲染错误；BDN 输出无效 |

v0.6 会将不适用的选项禁用：裁剪和 PG 缓冲优化只控制兼容核心；严格写出只控制兼容 SUP。调色板 PNG 可用于兼容 BDN，也可用于现代模式 720p/1080p 的**仅 BDN**输出（`-q 255 -r`）。现代 SUP、SUP+BDN 和高分辨率 BDN 的中间 PNG 使用 RGBA，SUP 量化交给 SUPer，避免重复量化；高分辨率缩放后的 PNG 也保持 RGBA。

## GPU 与 `_cl` 警告

报错中的名称通常是 `_cl`（字母 c、小写 L），属于 PyOpenCL 的原生模块。缺少独立显卡不是唯一原因：集成显卡也可能提供 OpenCL；缺少 OpenCL 驱动 / 运行时、原生 DLL 的依赖或位数问题都可能导致导入失败。没有具体完整日志，不能确认是哪一种。本机此次测试未复现该警告。

GPU 开关默认关闭，仅在现代模式输出 SUP 时启用。它控制 SUPer 的图像相似度 SSIM 计算，**不会把 libass 字幕渲染或整个 SUP 编码都移到 GPU**。选择 GPU 也不保证实际加速或更快，设备能力由上游判断。源码依据：[SSIMPW](https://github.com/cubicibo/SUPer/blob/v0.2.8/SUPer/utils.py)、[配置应用](https://github.com/cubicibo/SUPer/blob/v0.2.8/SUPer/interface.py)。

SUPer v0.2.8 读取其 EXE 同目录下的 `config.ini`，并无本版本可用的 `--no-gpu` CLI 参数。程序持有独占配置锁、按所选模式写入 `[SUPer] use_gpu=0/1`，编码器退出后恢复原配置字节；多个本程序实例不会互相覆盖。运行目录需可写。不要在编码期间直接从别处启动同一套 SUPer CLI，它不会遵守本程序的配置锁。

**关闭 GPU 可以关闭实际 GPU 计算，但不能保证消除启动期 `_cl` 警告。**该版本在读取配置前导入 SSIM_PIL，可能已触发 OpenCL 探测。此处保留上游 EXE 与 PyOpenCL 可选组件，保留原始日志。若要彻底避免此探测，需要修改上游为按需导入并重新构建 SUPer；不能靠隐藏错误行宣称问题已修复。资料：[supercli.py v0.2.8](https://github.com/cubicibo/SUPer/blob/v0.2.8/supercli.py)、[config.ini](https://github.com/cubicibo/SUPer/blob/v0.2.8/config.ini)、[PyOpenCL 运行时要求](https://documen.tician.de/pyopencl/misc.html)。

## 免安装字体

选择“字体目录（可选）”后，程序递归读取 TTF / OTF / TTC，字体检查同时识别目录内字体的内部别名。兼容模式在当前 Windows 会话临时加载字体并通知窗口，批次结束后逐个卸载。临时字体在加载期间也可被其他程序看到；不复制到 Windows 字体目录，不写字体安装注册表。不能只使用 `FR_PRIVATE` 或 WinForms `PrivateFontCollection`：它们只在主进程可用，外部 avs2bdnxml / VSFilterMod 看不到。

现代模式不注册会话字体，将字体复制到独立任务目录后通过 `--fontdir` 直接交给 libass。文件名可为中文、目录可有空格和子目录；ASS 必须引用正确的字体内部名称。同名的系统字体与目录字体并存时，选择优先级仍由渲染器决定；本程序不保证强制覆盖。字体文件损坏、格式不支持、字体缺字或 ASS 字体名称写错，都不会通过“选择目录”自动修复。
