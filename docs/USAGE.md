# Windows 使用说明

[返回项目首页](../README.md)

## 快速开始

1. 解压运行包，启动根目录的 `SupCraft.exe`。保留 EXE 与旁边 `tools/` 文件夹的相对位置。
2. 点击“添加 ASS…”一次选择多个文件，或把 ASS 拖入窗口。
3. 输出目录默认留空，SUP / BDN 直接保存到每个 ASS 各自所在的目录；如需集中输出，可手动选择目录。不会自动创建 `subtitle-output` 文件夹。
4. 如有配套字体，选择“字体目录（可选）”；程序会读取其中的子文件夹。留空则使用系统字体。
5. 点击“字体管理”查看缺失项并按需批量替换字体，按字幕的制作环境选择转换核心。
6. 设置分辨率、与视频一致的帧率和输出格式，再点击“开始批量转换”。
7. 查看任务列表中的完成或失败状态；双击任务可查看输出路径或错误摘要。

Windows 界面右上角提供“深色模式 / 浅色模式”切换，当前会话内即时生效。默认窗口以 1280×840、正文 12 px 为缩放基准；上方两栏高度固定为 552 px，文件列表可完整显示 8 行；转换设置面板尺寸固定，横向新增空间分给文件区，纵向新增空间分给日志区。转换状态、已运行时长和进度条位于右侧“开始批量转换”按钮上方。

任务按顺序执行，单个文件失败后会继续处理下一项。转换期间队列和参数会锁定；“取消当前批次”停止当前任务与后续任务，已完成输出保留。关闭转换中的窗口会先取消批次并清理临时字体和配置。

## 运行环境

- 使用 Windows，现代 SUP 编码所附带的 SUPer 需要 **64 位 Windows**。
- **兼容模式需要另外安装 32 位 AviSynth+**；只安装 64 位 AviSynth+ 无法供本程序的兼容核心使用。
- **现代模式不需要安装 AviSynth**。运行包已附带 ass2bdnxml、SUPer 及其运行依赖，无需另外安装 Python。
- 应用目录、输出目录和临时目录需要可写；现代 SUP 编码会临时修改并恢复 `tools/super/config.ini`。
- 无独立显卡也可以使用默认的 CPU 模式。GPU 加速另需兼容的 OpenCL 设备、驱动及运行时。

## 两种转换模式

默认使用 libass；AviSynth 用于按 VSFilter / VSFilterMod 校对的字幕。渲染差异、PGS 限制和各项参数的技术解释见[核心与选项详解](MODES-AND-OPTIONS.md)。

## 转换参数

| 参数 | 可选值或作用 |
| --- | --- |
| 分辨率 | 720p（1280×720）、1080p（1920×1080）；Windows 兼容模式另有 1440p（2560×1440）、2160p（3840×2160）和自定义 Beta；现代模式高分辨率仅支持 BDN |
| 帧率 | 23.976、24、25、29.97、50、59.94 fps；需要自行按目标视频设置 |
| 输出格式 | SUP、BDN XML + PNG、SUP + BDN XML / PNG |
| 语言代码 | 写入输出元数据，默认 `zho`；不会翻译字幕 |
| HDR / BT.2020 | 仅现代模式：渲染时缩减字幕 RGB 亮度；输出 SUP 时使用 BT.2020 矩阵 |
| 亮度缩减 % | HDR 选项开启后可设置 0–100%，默认 33% |
| GPU 加速（OpenCL） | 默认关闭；仅现代模式包含 SUP 输出时可选，控制 SUPer 的图像相似度计算 |

默认参数为 libass 现代模式、1080p、23.976 fps、SUP。选择 libass 时显示 HDR、亮度和 GPU 选项；选择 AviSynth 时显示自动裁剪、调色板 PNG、PG 缓冲优化和严格 SUP 写出，不再显示两组选项标题。程序不会读取视频来自动识别分辨率或帧率。

Windows 的 AviSynth 兼容模式可直接选择 1440p、2160p，或选择“自定义 Beta”输入宽、高（64–4096 的整数），例如 **1440×3200**。三者均在分辨率下方显示“非蓝光标准尺寸”提示。自定义宽和高须分别为 4 的倍数；输入时实时显示下方红色提示，并标红相应输入框，修正前无法开始转换。加减按钮以 4 像素为步长，输入无效值后也可用按钮调整到相邻有效尺寸。字幕按目标画布原生渲染，支持 SUP、BDN 和两者同时输出；不修改原 ASS，也不裁切或编码视频。批量转换期间宽高锁定，切换到 libass 模式恢复原有预设。

自定义画布不保证蓝光合规。SUP 需要目标播放器支持该尺寸；BDN 的 `VideoFormat` 写为明确的 `宽x高`（如 `1440x3200`），属于需要下游工具支持的扩展标记。全屏图形或密集动画仍受 PGS 缓冲和解码时序限制。此功能不适用于 Mac 版本。

**现代模式的 1440p / 2160p BDN 是将 1080p 渲染图像、坐标和画布同步缩放得到的结果，并非原生高分辨率 libass 渲染。**仅现代模式选择这两项时锁定为 BDN 输出。Windows 兼容模式则原生渲染，并可生成对应尺寸的 SUP。

Windows 界面采用左侧任务/目录、右侧转换设置、底部日志的分区布局，使用圆角输入框、自绘下拉菜单、状态标签和细滚动条。标题栏与应用顶部合并，保留拖动、双击最大化、边缘缩放、最小化/最大化/关闭和工作区边界处理。右侧设置在窄窗口或大字号下可滚动，开始/取消按钮保持可见。进度区显示批次“已运行 HH:MM:SS”：每批重置，完成、失败或取消后停止并保留最终时长，超过 24 小时继续累计小时数。

HDR 选项提供字幕亮度缩减和 SUP 编码矩阵选择，未实现完整的 PQ / HLG 色彩管理。

## 字体目录与字体检查

选择字体目录后，程序递归读取 **TTF、OTF、TTC** 文件，同时识别字体内部名称和别名。目录可包含中文、空格和子文件夹，无需将字体永久安装到 Windows。

- **兼容模式：**批次开始时临时加载字体，完成、失败或取消后卸载。加载期间，其他程序也可能看到这些会话字体。
- **现代模式：**将字体复制到任务临时目录，再通过 `--fontdir` 交给渲染器，不向 Windows 注册字体。
- **字体管理：**打开后检查当前队列的 ASS，按字体汇总使用文件，缺失项标红；“查看”可列出完整 ASS 路径、样式及行号。可多选字体，从已安装字体及所选字体目录（递归）的实际字体家族中设置替换；点击“保存替换（自动备份）”统一写入样式和 `\fn` 行内引用，仅修改字体名称。原文件同目录自动创建 `backup` 文件夹，将原 ASS 备份为 `.ass` 文件；已有同名备份时自动添加时间标记，保留之前的备份，其他样式字段及原编码保持不变；若字体名无法用原编码保存则拒绝该文件，请先另存为 UTF-8。保存后重新检查字体，修改过的任务恢复为等待。
- **完整路径：**将鼠标停留在任务列表的 ASS 文件单元格，悬浮提示显示完整路径。
- **导出报告：**保存 UTF-8 文本报告。
- **收集可用字体：**将能够定位到文件的已引用字体复制到所选目录；不能保证每个字体族都能收集到文件。

缺失字体会记录警告，转换仍可能使用替代字体继续，字宽、换行和位置也可能改变。ASS 必须引用正确的字体名称；选择目录不能修复损坏的字体、缺字或错误引用。同名系统字体与目录字体并存时，优先级由渲染器决定，程序不保证强制覆盖。

## 字幕预检与尾部保护

程序读取 UTF-8（有或无 BOM）字幕；UTF-8 解码失败时尝试 GBK。每个任务会检查 Events 字段结构、非空事件的时间格式及时间范围，并识别脚本分辨率与字体引用。

空事件处理（自 v0.6.1 起）：

- 跳过字段结构正确、`Text` 为空或全为空白的 `Dialogue`。
- 被跳过的事件不计入有效事件数，也不用于计算最后结束时间；日志汇总数量和原始行号。
- 仅清理转换时的临时副本，**原 ASS 保持不变**。
- 包含标签或绘图命令的事件仍保留检查；非空事件时间错误、字段缺失仍会报错。
- 全部事件均为空时，任务会提示没有可转换内容。

兼容模式按最后结束时间额外增加 2 秒渲染长度。现代模式会核对 BDN 尾部；检测到末尾缺失时，尝试仅移除临时副本中尾部事件的 `\fad` 后重试。仍无法满足尾部检查时报告失败。

### 常见问题

**提示 AviSynth 无法加载**

检查是否安装了 32 位 AviSynth+。若使用现代模式，则不需要 AviSynth；组件缺失时应重新解压完整运行包。
